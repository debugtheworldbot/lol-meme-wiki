# 研发.lol 设计实施

本技能仅用于本仓库，不改变其他项目或全局设计偏好。设计目标是让读者查含义、找出处、继续阅读。

## 规范入口

先读仓库根目录的 [DESIGN.md](../../../DESIGN.md)，它是视觉、页面结构与交互约定的唯一来源。
工程、数据、依赖及提交要求沿用 [AGENTS.md](../../../AGENTS.md)。不在技能里另存颜色、字号或完整组件清单。
如果通过其他客户端的 symlink 进入，以上链接仍指向同一个仓库根目录。

用户当次明确提出的新方向优先；按要求完成改动，并同步受影响的规范。不要因既有设计约定再向用户发起确认。

## 应用到当前任务

1. **确定范围。** 查看工作区状态，辨认本次要改变的页面及状态。用 `DESIGN.md` 的“页面结构与复用入口”找到现有模板，再读对应组件与样式；不要重做不相关页面。
2. **沿用层级。** 先确认主要阅读／操作路径，再调整内容顺序、字号、间距和状态。新说明页、详情页、目录或表单优先复用对应组件；需要新样式时使用现有语义令牌，修改原规则而非不断追加覆盖。
3. **保留契约。** 查清涉及的是行内搜索、全局搜索还是目录筛选，按各自规则实现。保留完整来源、编辑注、日期含义、关联入口、SEO 和已有分析事件；不通过伪造文案或删内容换取视觉整齐。
4. **检查恢复路径。** 对本次改动涉及的加载、空、失败、成功、键盘和返回状态作出处理。随机精选尤其要检查刷新、站内返回和浏览器后退，保持标题、摘要、链接和来源同步；不改成定时轮播。

常规局部修改无需再次搜索设计资源、安装 UI 库或生成多套概念稿。用户明确要求探索新方向时，再按其范围选择参考与方案。

## 验收与交付

- 可见 UI 改动在浏览器里操作实际路径，按 `DESIGN.md` 的“实施与验收”检查适用宽度和状态。截图用于说明结果，不能代替点击、键盘或返回路径验证。
- 检索相关修改检查 IME、失焦点击、更多结果及焦点；表单相关修改检查标签、校验、草稿与三态结果，使用可控本地场景，不产生真实投稿。
- 依 `AGENTS.md` 选择相关 lint／typecheck；路由、metadata、内容集合或生产配置变化再做构建。纯文档变更只校验文档与技能结构。
- 若本次改变了可复用设计决策，同步更新 `DESIGN.md`；只在流程或触发范围变化时修改本技能或 AGENTS。引用外部原则不代表本项目依赖外部技能的安装。
- 完成后按仓库规则提交这一个逻辑增量，说明行为变化、已验证路径、未验证边界和提交；用户只要求评审时输出发现，不据此改代码或提交。
