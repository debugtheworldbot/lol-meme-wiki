# Search Console 每周 SEO 表

用于把 Search Console 的真实查询转成内容动作。只记录可复查的数据与已经执行的改动，不用搜索量猜测代替站点数据。

## 固定口径

- 每周二复查一次，使用截至上周日的完整数据，避开最近两天的数据延迟。
- 查看 `搜索结果 → 网页`，同时导出“查询”和“网页”。
- 周表使用最近 7 天；趋势判断再对比前 7 天。样本仍小时，同时参考最近 28 天。
- Search Console 是曝光、点击、CTR、排名的数据源；Plausible / Vercel Analytics 只用于判断进入站点后的行为。
- 内容更新必须有新增信息，不为制造“新鲜度”只改 `updated_at`。

## 机会分级

| 级别 | 条件 | 动作 |
| --- | --- | --- |
| P0 | 曝光 ≥ 10、CTR = 0、平均排名 ≤ 10 | 检查搜索意图；补标题首句、别名、出处和正文答案 |
| P1 | 曝光 ≥ 5、平均排名 4～15 | 补内容深度、上下文和站内链接 |
| P2 | 查询已有曝光，但没有准确落地页 | 新建词条或专题页；不要用不相关页面硬接 |
| 保持 | 已有点击或 CTR ≥ 10% | 保留标题主意图，从专题页和相关词条增加内链 |
| 观察 | 平均排名 > 30 或曝光 < 3 | 暂不为单个查询改页，等待更多样本 |

## 每周更新步骤

1. 打开 Search Console 的“效果 / 搜索结果”。
2. 选择截至上周日的 7 天，并打开点击、曝光、CTR、平均排名四项指标。
3. 查询表显示 100 行；网页表显示 100 行。把达到 P0/P1 条件的行复制到本页顶部。
4. 先按网页聚合，再查看该网页对应的查询，避免同一页面被多个近义词重复计算工作量。
5. 每周最多处理 10 个页面。优先修正答案缺口，不为同义查询拆出重复页面。
6. 改完后记录 commit、状态和下次复查日期。至少等待一周再判断 CTR，样本不足时延长到 28 天。
7. 新专题或新词条上线后，确认 canonical、sitemap、内部链接和 URL Inspection 均指向同一地址。
